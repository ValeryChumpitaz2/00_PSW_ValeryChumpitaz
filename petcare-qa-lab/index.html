🐾 EJEMPLO PRÁCTICO

PetCare

Un pequeño sistema para comprender cómo se aplican las pruebas de software.

EL ESCENARIO

Antes de publicar una funcionalidad, debemos comprobar que funciona.

PetCare es una pequeña aplicación web para registrar citas veterinarias. Utilizaremos este ejemplo para recorrer un proceso básico de pruebas de software.

01
🔎
ANALIZAR

¿Qué podría fallar?

Antes de probar necesitamos conocer qué hace la funcionalidad y qué situaciones podrían generar errores.

Ejemplo

¿Qué ocurre si el usuario intenta registrar una cita con una fecha anterior?

02
📝
DISEÑAR

Definir el caso de prueba

Convertimos el posible error en un escenario concreto que podamos ejecutar.

Caso de prueba

Registrar una cita utilizando una fecha anterior a la actual.

03
👩🏻‍💻
EJECUTAR

Realizar la prueba manual

Una persona interactúa con el sistema, introduce los datos y observa el resultado.

Resultado esperado

El sistema debe impedir el registro y mostrar un mensaje de validación.

04
📋
REGISTRAR

Comparar resultados

Comparamos lo que esperábamos obtener con lo que realmente ocurrió.

Resultado

✔ La fecha fue rechazada. La prueba pasó correctamente.

05
AUTOMATIZAR

¿Qué cambia cuando automatizamos?

👩🏻‍💻
PRUEBA MANUAL

Una persona ejecuta

1 Abrir PetCare
2 Ingresar datos
3 Seleccionar fecha
4 Verificar resultado
👀 Requiere intervención humana
🤖
PRUEBA AUTOMATIZADA

El código ejecuta

1 Abrir aplicación
2 Ingresar datos
3 Ejecutar prueba
4 Verificar resultado
⚡ Puede repetirse rápidamente
🤔 Entonces, ¿cuál es mejor?

Ninguna reemplaza completamente a la otra. Las pruebas manuales son útiles para explorar y observar el comportamiento del sistema; las automatizadas son ideales para repetir verificaciones de forma rápida y consistente.
